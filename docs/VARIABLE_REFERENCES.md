# Variable References

Last updated: 2026-05-07

## Overview

The application calculates conditions with deterministic Python rules. The main
app-facing path builds a `ScoreInput` in `src/kenai_engine/report_builder.py`,
then scores it in `src/kenai_engine/scoring.py`. A newer pure condition engine in
`src/kenai_engine/fishing_conditions.py` accepts richer hydrology, tide, weather,
biological, access, and freshness snapshots and returns explainable component
scores. Legal closures and restrictions override ordinary condition quality.
Source freshness lowers confidence and can reduce final score quality.

The TP information database is the local SQLite database initialized by
`src/kenai_engine/db.py`. The new `condition_variables` table stores variable
metadata and is seeded from `src/kenai_engine/condition_variables.py` whenever
`initialize_database()` runs.

## Assumptions

- “TP information database” is interpreted as the local SQLite engine database initialized by `src/kenai_engine/db.py`; there is no separate migration framework or TP-named table in this repository.
- New TP variables were added as metadata records, not as active score inputs, unless an equivalent variable already existed in the calculation path.
- Exact-name duplicates were avoided. `tide_stage` already existed and is documented once; related existing fields such as `hours_until_high`, `height_delta_ft`, and `tide_phase` are retained under their current names.
- Tide heights are documented in feet relative to MLLW because the NOAA adapter requests `units=english` and `datum=MLLW`.
- Astronomical times are documented as local times for the target location/date because USNO `rstt/oneday` supports location, time zone, and daylight-saving parameters; the application does not yet fetch those values.
- Date accessed for all web references is 2026-05-07.

## How To Update This File

1. Add or update the canonical metadata row in `src/kenai_engine/condition_variables.py`.
